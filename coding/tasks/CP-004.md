## 2. Outcome

Provide the reusable owned-path and publication boundary needed for later config/plan/report artifacts. The primitive reports the real commitment state when storage errors occur.

## Required input package

- CP-003 resource/artifact/schema contracts.
- Declared owned path roots, source-read versus destination-write authority and synthetic test identities.
- Actual supported filesystem/OS behavior and fault-injection method for unprivileged fixtures.

## Allowed source areas — convert to an exact allowlist at activation

- Filesystem/resource/publication primitives under `src/actools/`.
- Pure helpers and isolated filesystem/failure fixtures under `tests/`.
- Owned-destination policy/ADR and publication troubleshooting documentation.

## Implementation requirements

- Perform descriptor-relative protection checks and operations appropriate to the qualified platform. Reject traversal, symlink substitution, special files and unowned/protected destinations; do not rely on a check-then-open pathname alone.
- Source disclosure and output ownership are separate decisions. A writable output destination does not permit reading a protected result.
- Validate/render completely into protected staging before replacement. Failure before commitment preserves the previous valid artifact; failure after replacement/sync reports observed state or uncertainty and cleanup obligations.
- Use narrow source and staging ownership/modes; secrets/canaries and unexpected raw payloads must not appear in errors.
- Destination policy excludes managed code/config/state/secret paths for caller-selected plan/report outputs. Internal managed-publication handlers remain separate owned uses of the same safe primitives.
- Retain finite byte/inode/temp-file and cleanup bounds. Cleanup only verified owned artifacts and never broad recursive deletion of caller-controlled paths.

## Meaningful proposed acceptance tests

- Traversal, symlink swap, wrong owner, parent swap and special-file corpus cannot redirect reads/writes beyond authority.
- Full disk, short write, rename failure and sync failure exercise both pre-commit and post-replacement outcomes.
- Concurrent access/race fixtures demonstrate actual opened object identity, not only normalized string equality.
- Existing artifact remains intact before commit; after uncertain durability, output does not falsely claim old artifact preservation.
- Secret-canary input and malicious filenames remain redacted/literal in diagnostics.

## Documentation and changelog work

- Permitted output destinations, ownership and overwrite behavior.
- Publication states and operator response to export/sync failures.
- Resource/cleanup boundaries and exact platform qualification limits.

## Excluded from this slice

- No arbitrary root file writer, generic copy/delete interface or live system-path testing.
- No first-release HTML renderer or actual configuration activation yet.
