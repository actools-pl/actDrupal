## 2. Outcome

Provide a fixed subprocess API, secret-reference/error discipline and data-only handoff boundary that later handlers/renderers can consume without inheriting authority.

## Required input package

- CP-004 protected files/resources.
- Reviewed fixed executable registry and intended minimal identities/environment; fixture-only executables initially.
- CP-003 result/error/disclosure contracts and finite process/IPC budget fields.

## Allowed source areas — convert to an exact allowlist at activation

- Internal subprocess, environment, redaction and handoff modules under `src/actools/`.
- Bounded synthetic child/handoff fixtures under `tests/`.
- Secret handling, trusted output and process-boundary documentation.

## Implementation requirements

- Pass literal argv without a shell, use owned fixed executable paths and controlled cwd/environment/import behavior; callers cannot choose a privileged binary, module, UID, daemon or unchecked flags.
- Bound execution time, stdout/stderr/IPC bytes and cleanup. Required safety bookkeeping must be independent of a consumer draining output; integration with the journal follows CP-007.
- Use secret references and suitable protected descriptor/file delivery. Never put secret values in argv or ordinary results; validate ownership/authorized disclosure before loading.
- Represent external diagnostics as literal attributed evidence. Only owned mappings create next actions/documentation URLs; terminal control/library markup cannot turn source text into trusted UI.
- Define the actual unprivileged plain-data handoff and prove identity/groups/capabilities/descriptors/environment at its boundary using fixtures. It cannot collect more data or call the privileged helper.
- Sanitize/redact failure paths too: validation exceptions, child failures, process teardown, handoff loss and publication errors. Preserve safe typed error codes and useful non-secret context.

## Meaningful proposed acceptance tests

- Quotes/newlines/metacharacters remain argv data; PATH/env/import/cwd substitution and caller executable overrides fail.
- Synthetic child timeout, excessive output, broken pipe and slow reader end within declared budgets without leaked child processes.
- Canaries in rejected input/exception context/environment and child output stay absent from every returned channel/artifact.
- Handoff fixture cannot read protected sentinel or retain an unintended privileged descriptor/group/capability.
- Hostile instructions, terminal control characters and fake status/URL text cannot alter trusted action mappings.

## Documentation and changelog work

- Allowed execution context, secret references and redacted diagnostics.
- What is safe to return to a coding/review chat and what stays local.
- Expected timeout/child failure/handoff outcomes and remaining installed qualification.

## Excluded from this slice

- No application bootstrap as root, generic shell runner, live credential rotation or real HTML rendering.
- A unit fixture is not proof of the eventual installed sudo/helper boundary; repeat applicable tests when that boundary exists.
