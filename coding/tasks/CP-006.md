## 2. Outcome

Implement one protected local journal with durable intent/state records, qualified read/write boundaries and fixture-based crash reconciliation. This establishes bookkeeping before any real effect handler.

## Required input package

- CP-003 journal/evidence/result schemas and CP-004/005 safe access/error primitives.
- Exact Python/SQLite library and qualified local filesystem in the development environment.
- Synthetic operations/effects/state transitions and failure boundaries; no live host actions.

## Allowed source areas — convert to an exact allowlist at activation

- Operation store and state-transition code under `src/actools/`.
- SQLite/open-mode/state compatibility/failure fixtures under `tests/`.
- Operation-state/journal recovery runbook and storage ADR.

## Implementation requirements

- Use accepted SQLite `journal_mode=DELETE`, `synchronous=EXTRA`, one protected writer and 5000 ms busy timeout, plus finite operation deadlines. Verify effective settings on each relevant open.
- Use the existing management identity/owned store policy. Application writers and future renderers have no store access; no second cross-host journal or job authority is introduced.
- Persist intent before an effect could be admitted. State transitions retain authenticated actor/plan/effect identity, attempts/deadlines, observed outcomes, reconciliation class and cleanup obligations.
- Represent pending/running/succeeded/failed/blocked/interrupted explicitly. Ambiguous outcome blocks dependent effects; a display failure cannot rewrite an already recorded successful effect.
- Provide a genuinely read-only inspection path. If opening would require recovery writes, block and report the proper reconciliation path; plan must not initialize or heal a journal.
- Reader/writer schema compatibility and supported backup/recovery API are explicit. Actual power-loss durability remains a later installed filesystem/platform qualification; SQLite flags alone do not prove it.

## Meaningful proposed acceptance tests

- Verify effective PRAGMAs and access ownership on the chosen local environment.
- Missing store and recovery-required journal reject through the read-only path without creating directories/rows/files.
- Kill/fail fixture writer before/after recorded intent and commit; reopening classifies state honestly and cannot invent success.
- Competing writer/busy timeout and storage/sync failures have finite typed outcomes without losing accepted prior rows.
- Simulated result-delivery failure leaves committed operation truth inspectable; synthetic secret canaries do not enter records/output.

## Documentation and changelog work

- Operation state meanings, evidence versus durable outcome and safe inspection.
- Journal contention/corruption/recovery procedure with explicit stop conditions.
- Qualified library/filesystem scope and remaining crash/power-loss tests.

## Excluded from this slice

- No actual host effect, production store, automatic restart, arbitrary journal repair, or fixture apply command yet.
- Resource-wide locking/backpressure integration is CP-007; true plan/init is CP-008; fixed reversible executor is CP-009.
