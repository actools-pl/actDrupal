# Software changelog entry template

This is for the installer repository's `CHANGELOG.md`. Package workflow changes belong in `PACKAGE_CHANGELOG.md` instead.

## Unreleased — <category: Added / Changed / Fixed / Removed / Security>

- <Concrete operator-visible change and resulting behavior.>
- Compatibility: <schema/default/profile/upgrade impact, or none with reason>.
- Operator action: <qualified runbook link, or none>.
- Limitations: <unsupported or unqualified affected cases; no implied release support>.
- Traceability: <task/PR and exact accepted source change>.

Before release: combine duplicate entries, verify against the exact candidate, place under a real version/date only when released, and link the release record. Do not include secrets, raw diagnostic content, invented performance gains or unreleased capabilities as shipped features.
